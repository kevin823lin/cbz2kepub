# 驗證結果

驗證環境：Windows、Python 3.13.7。目前 KCC 固定 `5f4e5ad`；下表的實際資料成品來自先前 `d170828` 的完整驗收，本次封裝與預檢修改尚未重跑該完整驗收。

| 項目 | 結果 |
|---|---|
| 單元測試 | 主專案 69 項、KCC 31 項，共 100 項通過 |
| CLI 整合 | 5 個情境、8 次轉換通過，包含跨工作目錄啟動 main.py、分卷、metadata 與不備份重跑 |
| 實際資料 | 70 個 CBZ、2,929 個正文頁、70 個正確章節入口 |
| 成品 | 1 卷，1,328,139,120 bytes，低於 2 GB 上限 |
| 封面 | 第一個閱讀頁且置中；1260×1680 JPEG 與獨立重建參考圖一致 |
| Metadata | 作者、簡介及尾端換行、系列名與卷序均正確 |
| 完整性 | ZIP CRC、XML、資源引用、正文及章節順序通過；來源 SHA256 未變 |
| 工作區 | 70 個 CBZ 使用硬連結；成功後無工作目錄、交易或鎖殘留 |

測試與驗收命令見 [開發指南](contributing.md#測試)。

本次只讀取同一批 70 章來源重算預估，未轉檔或發布：圖片預估由 3,745,628,632 降至 1,602,435,371 bytes；含 32 MiB 餘裕、未抵扣舊成品刪除的 work 峰值預算由 7,715,196,368 降至 3,272,686,059 bytes。這是分層抽樣與一次封裝的預算比較，不是實測占用峰值。測試另驗證最大樣本只影響所屬區段、處理前保留分層預測、各卷實際封面編碼，以及 7z 可用時 EPUB 仍只寫一次且 mimetype 位於首筆。

尚未涵蓋 Kobo 實機、全面畫質比較、全新環境重建，以及實體跨磁碟／斷電測試；一般容量不足與發布失敗已用受控測試驗證。
