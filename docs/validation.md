## 第 2 話 Kobo 橫向閱讀接縫（2026-11-08）

第 48／49 頁與第 50／51 頁的左右配對正確。四頁均保留完整原圖，輸出為 1123×1680 JPEG。電腦直接拼接成品 JPEG 時，靴子的黑塊連續，灰底網點在原圖邊緣已有些微差異。使用者在 Kobo 橫向閱讀時，於這兩處看見細線。

| 接縫樣書 | 封裝方式 | Kobo 實機觀察 |
|---|---|---|
| A（正式版） | 左右各一個 XHTML，各顯示一張 JPEG，viewport 等於圖片尺寸 | 可見細縫 |
| B（單頁定位） | 沿用 A 的兩頁與 JPEG，將圖片固定在各自 XHTML 的左上角 | 細縫仍在 |
| C（合圖） | 將兩張成品 JPEG 的解碼像素無損拼成一張 PNG，放入單一 2246×1680 XHTML | 無可見細縫 |
| D（同頁雙圖） | 沿用 C 的單一 XHTML 尺寸，兩張獨立 JPEG 分別從 x=0、1123 貼齊 | 細縫仍在 |

這次只有 C 在受測裝置上達到無縫。D 與 C 共用相同的 viewport，兩張 JPEG 的解碼像素也與 C 的左右兩半逐像素一致。細線的確切繪製原因仍未確認。正式輸出繼續採用每張圖片一個閱讀頁，暫不採用合圖，橫向接縫列為已知限制。

## 第 43 話 Kobo 實機 viewport 對照（2026-11-08）

使用者在同一台 Kobo 比較兩本 RTL 樣書，兩本的 JPEG 與 CSS 相同。三組正文依序為等寬彩色跨頁、保留中央接縫並只裁掉右頁外側的異寬跨頁，以及原本就寬度不同的兩張普通頁。

| 觀察 | A：viewport 等於各自 JPEG 尺寸 | B：viewport 固定 1264×1680 |
|---|---|---|
| 直向 | 影像上下貼合、左右置中 | 影像上下貼合、左右置中 |
| 橫向 | 三組左右內緣均貼齊。異寬跨頁上下對齊 | 三組圖片四周都有留白，中央接縫分開 |
| 異寬接縫組的 CSS 診斷 | 橫向閱讀時仍顯示 P | 橫向閱讀時仍顯示 P |

因此正式採用 A 版。這是使用者回報的裝置觀察；不同機型與韌體的效果需分別驗證。

正式 KCC `f071180` 以 KoLC、RTL、cropping=2 轉換整個 39 頁章節，得到 19 組雙頁和 1 個置中孤頁。從成品 ZIP 讀取的 39 張正文圖片都與自己的 XHTML viewport 同尺寸。第 1、2、23、24 頁的 JPEG 與實機樣書所用的四張自然頁 JPEG 的 SHA256 完全相同；章首兩張均為 1170×1680，第 23、24 頁分別為 1186×1680 與 1105×1680。

主專案 94 項單元測試、KCC 78 項單元測試與 7 個 CLI 情境通過。合成測試涵蓋寬度先達 profile 上限、禁止放大、同高異寬的頁對，以及孤頁裁後變寬仍輸出一個閱讀頁。含橫向或正方形原圖的章，則以啟用與關閉章內配對的原生圖片逐位元組核對。

同版本的完整驗收得到 1 卷、1,303,278,935 bytes、70 個章節入口及 2,929 個正文頁。從成品重讀 ZIP、JPEG 標頭、XHTML 與 spine，核對 1,443 組雙頁及 43 個置中孤頁。其中 987 組雙頁左右異寬，所有雙頁組都等高，各張圖片均與其 viewport 同尺寸。5 章由接縫決定基準，65 章採作品的 spreadshift。完整書的四張實機對照頁 JPEG 雜湊也吻合。第一個置中封面、作者、簡介、系列與卷序通過核對，來源 CBZ、封面與作品資料的 SHA256 維持一致。

同一批兩章共 60 頁，一章高度相同且使用設定基準，一章混合高度且從章首辨識到跨頁。兩種模式各暖機一次，接著交錯測量三輪。下表採各模式三個測量值的中位數。

抽查的彩色章首頁對確實是同一幅圖。兩半內容均為 1170×1680，放入 1264×1680 畫布，各自外側補 94 像素，中央接縫與上下位置對齊。另抽查的普通頁兩半內容寬度分別為 1154 與 1138 像素，均維持 1680 像素高，保留各自的水平裁切。

## 測試與界線

主專案 91 項單元測試、最終 KCC 72 項單元測試通過。7 個 CLI 情境涵蓋巢狀單 CBZ、Fusion 混合寬圖回退、長章名、不可拆頁對、封面、metadata、發布與舊設定相容。背景驗收腳本另以合成案例驗證 JSON 編碼、啟動版本、來源 SHA 與既有結果保護。

70 章驗收後，小圖合成測試在預設裁切模式重現原生邊緣取樣區寬度取整為零的問題。最終 KCC `1423b5e` 跳過零面積取樣區。原本失敗的兩個 CLI 案例均已通過。逐張檢查 2,929 張實際來源的尺寸，共九種寬高組合，觸發此條件的頁數為零。交付時另從已產生的 KEPUB 重新核對 ZIP、正文資源、配對、封面與 metadata。

全新環境重建、實體跨磁碟及斷電仍待驗證。成品結構、幾何與樣書抽查無法覆蓋所有掃描錯位或內側裁切造成的接縫問題。
